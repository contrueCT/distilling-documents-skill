# Human Writing Adaptation for Distillation

本文件把 `KKKKhazix/human-writing` 中最适合“文档精炼后改写”的规则收进当前 Skill，使 `distilling-documents` 可以独立运行。原项目采用 MIT License；来源与许可见 `THIRD_PARTY_NOTICES.md`。

这里保留的是它最有价值的原则：**自然中文来自具体材料、清楚的说话位置和顺畅的句法，不来自刻意口语化。** 本文件只处理表达，不重新决定信息删留。

## 1. 先服从当前文类

“说人话”不等于聊天口吻。

- 技术 / 设计文档：正式、克制、直接。术语、标题、列表、条件和接口名该留就留。
- 技术分享 / 博客：像真正懂材料的人把来龙去脉讲清楚，可以更自然地展开因果和判断。
- 新闻 / 行业信息：事实先站稳，来源说法、作者判断和未知保持边界。
- 资料 / 知识整理：句子可以短，但不能只剩碎片；每个信息包尽量自己完成理解工作。
- 教程：顺序、前置条件和动作优先；读者应该能照着做。
- 研究 / 报告：允许正式书面语，重点降低句法负担和抽象套话，不把它改成自媒体口吻。

具体文体覆盖通用风格。不要为了“活人感”破坏原本成立的专业结构。

## 2. 每一段都要往前走

检查后一段新增了什么：事实、解释、例子、区别、后果、条件、反例或判断。

如果只把上一段换一种说法，合并或删除语言重复。推进应靠材料和因果，不靠这些模型常用路标：

- “更深一层”
- “更微妙的是”
- “还有一层”
- “值得注意的是”
- “需要指出的是”
- “从某种意义上说”

它们确实承担必要逻辑功能时可以保留；只是给句子“抬高”时去掉。

## 3. 先让主语和动作出现

读者应该尽早知道“谁 / 什么做了什么”。原因、时间、条件和例子接在后面。

优先处理：

- 一句话堆太多“的”；
- 很长的定语把核心名词压到句尾；
- “进行了 / 实现了 / 完成了对 / 起到了……作用 / 具有……意义”一类名词化结构；
- 抽象名词连续出现，却看不出具体的人、动作、钱、时间、资源或后果。

不要机械切短。复杂关系可以用长句讲完，只要主干来得早、停顿清楚。

## 4. 把具体材料放在抽象判断旁边

能直接说清楚时，不要用机构腔兜一圈。

低信息表达：

> 该模型在硬件部署层面存在较高门槛。

高信息表达：

> 模型权重约 1.4～1.5TB，而 8 张 H200 总显存约 1.13TB，因此单节点无法完整加载。

精炼稿尤其要避免“能力强、门槛高、具有意义、带来影响”这种脱离事实的二次概括。如果保留判断，把依据放在附近。

## 5. 指代要让人一次读懂

顺着句子看“这 / 它 / 其 / 该方案 / 上述机制”到底指什么。

- 前一句有多个候选对象时，把名词写回来。
- 中间隔了一段解释时，把主语写回来。
- 指向清楚时，不必为了避免重复强行换代词。

中文自然不等于追求词汇不重复。为了指代清楚，重复一次专有名词通常比“其”“该模型”“这一机制”更好。

## 6. 不表演口语感

不要为了显得自然主动加入：

- “老铁”“兄弟们”“咱就是说”一类称呼；
- 粗口、错别字、连续省略号；
- 固定频率的括号吐槽；
- “说白了”“说穿了”“先说结论”这类表演性提示。

真正的自然感来自材料具体、判断有依据、句子顺、段落在推进。

## 7. 清理常见模型腔和商业黑话

遇到下面这类词，优先还原成具体的人、动作、资源、限制和结果：

`赋能`、`抓手`、`闭环`、`能力沉淀`、`拉通`、`认知跃迁`、`价值释放`、`能力建设`、`降本增效`、`全链路`、`组合拳`、`打开想象空间`、`关键命题`、`深层逻辑`、`技术底座`。

不要机械禁词。源材料本身把某个词当作正式术语、组织名称或必须保真的原话时保留。

避免为了制造“洞察”先立一个读者并没有的误解，再用固定翻案句抬高结论。能正面下判断，就直接说判断并把依据放旁边。

## 8. 现实材料守住来源边界

对事实型材料，内部区分：

1. 可靠来源直接证明的事实；
2. 公司、机构或当事人的自述；
3. 媒体或旁人概括；
4. 作者依据材料作出的推断；
5. 当前未知。

最终稿只在会影响判断的地方说明归属，不把核验笔记全部倒进正文。发布状态、价格、政策、许可证、职位、软件版本等会变化的内容，不能把旧材料改写成无时间边界的永久事实。

用户给出的经历不能被扩写成没有发生过的亲历。源材料没有的现场、对白、心理、动机、因果和数字都不能为了可读性补出来。

## 9. 数据写完走到“它意味着什么”，但不越界

关键数字旁边可以补上源材料已经支持的关系或后果，让读者不用自己拼。

例如：

> 8×H200 约 1.13TB < 1.4～1.5TB 权重，因此装不下。

如果源材料没有提供“为什么”“会导致什么”，不要自行创造因果。可以只保留数据和原文明确给出的判断。

## 10. 最后一遍只做语言审稿

初稿完成后快速检查：

- 有没有一段只重复上一段；
- 有没有抽象名词堆叠；
- 主语和动作是否出现得太晚；
- 长定语是否让人读到结尾才知道在说什么；
- 指代是否含糊；
- 有没有机构腔、营销腔或模型洞察路标；
- 有没有为了自然加入源材料不存在的事实；
- 有没有把正式文档改得过分口语；
- 标题、列表、冒号、表格、代码块等是否承担检索或执行功能。

**不要照搬原 `human-writing` 对散文的全局标点禁令。** 在技术文档、资料、教程和研究报告中，冒号、列表、表格、破折号、代码符号等可能是必要结构，按当前文类使用。
