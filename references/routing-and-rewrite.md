# Routing and Rewrite

这一文件只负责“最终稿应该长什么样”，不负责重新决定信息删留。自然中文的具体改稿规则放在 `human-writing-adapted.md`。

## Content Routing

| 内容类型 | 最终目标 | 默认结构倾向 |
|---|---|---|
| 技术 / 设计文档 | 准确、正式、容易扫读 | 保留标题层级、术语、条件、列表；围绕问题/方案/影响组织 |
| 技术分享 / 博客 | 让读者快速理解来龙去脉 | 连贯段落 + 少量小标题；原因和结论放在一起 |
| 新闻 / 行业信息 | 高密度、事实与判断分开 | 先给核心变化，再讲原因、影响、不确定性 |
| 资料 / 知识整理 | 以后能查、能快速定位 | 短段落或信息包；数字、定义、比较清楚可见 |
| 教程 / 操作说明 | 能直接照着做 | 保留步骤、前置条件、命令/配置和注意事项 |
| 研究 / 报告 | 保留结论成立的证据与边界 | 结论 + 方法/数据 + 限制；不要只留 executive-summary 式结论 |

一种材料可以同时具有多种功能。以读者未来最可能怎么使用它来决定结构，不必强行套单一标签。

## Rewrite Boundary

进入改写层时，信息选择已经完成。改写层可以：

- 重排句子和段落；
- 合并或拆分句子；
- 调整词序和主语位置；
- 把抽象报告腔改成具体、直接的表达；
- 根据文类调整正式程度；
- 保留必要的标题、列表、表格、步骤、代码块和配置项。

改写层不能：

- 新增源材料没有的事实、案例、动机和因果；
- 删除关键数字、条件、术语、反例和认识状态；
- 把“估算/推测/公司自述”改成确定事实；
- 为了活人感加入网络梗、口头禅、假装随意的语气；
- 为了统一风格破坏技术文档、教程和资料的检索结构。

最终改写后仍要回源材料快速复核一次。表达层不是第二个信息蒸馏阶段。
