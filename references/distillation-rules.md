# High-Fidelity Distillation Rules

仅在材料很长、信息密度高，或某条信息是否能删难以判断时读取。普通材料不要显式建立完整账本。

## 1. 内部识别的信息类型

优先识别：

- 核心结论
- 事实 / 数据 / 时间 / 版本
- 定义 / 机制 / 流程
- 因果 / 比较 / 依赖关系
- 条件 / 边界 / 例外 / 否定
- 证据 / 案例 / benchmark
- 判断 / 推测 / 预测 / 估算
- 反例 / 负面证据 / 风险
- 背景 / 铺垫 / 重复 / 修辞

不要因为某条信息出现次数少就认为它不重要。反例、限制和一次性的精确阈值经常只有一处。

## 2. 保真级别

### literal-preserve

关键数字、金额、日期、版本、专有名词、路径/标识符、阈值、License 条款、明确否定和关键限定。可以换句法，不得把精确内容泛化。

### semantic-preserve

定义、机制、解释、案例等可以降低展开程度，只要核心含义和它承担的作用仍在。

### optional

无独立信息量的过渡、修辞、重复强调、同类例子的冗余部分。

## 3. MERGE / COMPRESS / DROP

### MERGE

如果几条信息共同回答同一个问题，优先合并成一个 information packet。典型结构：

> K3 的 MXFP4 权重约 1.4～1.5TB，而 8 张 H200 总显存约 1.13TB，因此无法在这类单节点机器上完整加载。

它同时保留数据、比较和结论，比“部署门槛高”更能替代原文。

### COMPRESS

长解释可以降低粒度，但要保留其作用。比如三段 MoE 原理可以压成一句，只要仍解释“总参数很大但每次只激活一部分参数”的关系。

### DROP

只有在 MERGE 和 COMPRESS 都不适合后才考虑。

删除前快速检查：

1. **理解**：删掉后，读者还能准确理解这部分吗？
2. **解释**：重要结论还知道为什么成立吗？
3. **未来查询**：以后合理地回来查这条信息的概率高吗？
4. **边界**：会不会让说法更绝对、更宽泛或更确定？
5. **独立价值**：它是否提供新的阈值、反例、正向边界、证据或可复用事实？

任一项回答“会造成明显损失”，就不要直接 DROP。

以下内容原则上不能直接 DROP，除非已被另一个 information packet 完整覆盖：

- 关键数字和阈值
- 时间、版本、名称
- 限制、例外、否定条件
- “可能 / 估算 / 作者认为 / 截至某时”等认识状态
- 关键因果
- 核心定义
- 反例和与主结论冲突的重要证据
- 原文特别强调的风险

## 4. Source Anchors

对关键事实和 information packet 在内部保留页码、章节标题或段落锚点。长文分块时锚点必须随内容进入全局合并。

默认不把锚点写进最终稿。以下情况可以展示：

- 用户要求可追溯；
- 精确引语；
- 关键争议数据；
- 需要明确区分原文声称与外部事实。

## 5. Lightweight Verification

不要默认生成十个 Probe 问题。第二遍只做快速反查：

- 原文最值得以后查询的几件事，在精炼稿里还能找到吗？
- 主要结论的必要依据还在吗？
- 有无把推测升级成事实？
- 有无把“多数情况下”改成“总是”？
- 有无丢失会改变整体判断方向的负面信息？

发现缺口直接救回，不向用户展示检查过程。
